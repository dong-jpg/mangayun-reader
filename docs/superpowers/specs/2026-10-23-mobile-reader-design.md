# MangaYun Reader: 手机优先设计

日期：2026-10-23

状态：需求与主要设计已沟通；本文等待用户审阅，尚未进入实现。

## 1. 目标与环境

新建独立的漫画阅读油猴脚本项目，不修改现有的 `pixiv-novel-sync`。

- 首要环境：安卓、Chromium 系浏览器、Tampermonkey。
- 次要环境：桌面 Chromium 浏览器；不以桌面文件系统接口作为手机功能的前提。
- 首个适配网站：`https://mangayun.com`。
- 用户安装一个 `.user.js` 文件，不需要安装后端或提供账号密钥。
- 设置、阅读进度和任务数据留在本地，不上传阅读记录。
- 不要求用户先提供浏览器小版本；运行时检测必要能力，并展示明确的兼容性说明。

## 2. 方案选择

采用单一油猴脚本，内部拆分站点适配、阅读器和下载器，提供可退出的增强阅读界面。

另外两种方案不用于首版：仅修改原站 CSS 难以统一手势、单页模式和下载生命周期；单独开发浏览器扩展会增加安卓安装与兼容成本。

首版不做多站点适配、自动翻译、云同步、漫画搜索引擎、账号系统、自动更新监控、跨话无限拼接、双页对开或自动裁边。保留适配器边界，不提前实现这些功能。

## 3. 已核实的网站情况

本次通过真实网页观察到：

- 云漫聚合多个漫画源，同名漫画可能有不同来源和版本，不能只用标题作为标识。
- 搜索结果包含章节目录、正序/倒序切换及来源选择。
- 阅读路径采用 `/read/.../...`，在站内导航时可用弹层覆盖原搜索页。
- 当时阅读区为 `[role="dialog"][aria-label="漫画阅读器"]`，原站已有竖滑和翻页按钮。
- 示例章节的图片有顺序页码，前几页立即加载，其余使用懒加载。
- 示例图片地址包含 `x-expires` 和 `x-signature`，图片链接不能被当作永久标识。

这些是样本观察，不代表已经验证所有漫画源。实现时必须记录网站实际使用的目录和章节请求，建立响应样本测试；不能猜测接口路径，也不能把搜索页缩略图当作漫画页。

## 4. 阅读模式

### 4.1 日漫横向连续模式

- 当前话内的图片横向无缝相连，默认适配可用屏幕高度，保持原始比例，不裁切。
- 可选择从左到右或从右到左的阅读顺序；下一页始终表示逻辑页码加一。
- 阅读方向只改变排列和前进方向，不改变下载页序，也不镜像图片本身。
- 使用连续滚动，不强制一屏一页或每次滑动都吸附到页边界。
- 支持手指横向滑动；桌面鼠标操作为兼容功能。

### 4.2 韩漫纵向连续模式

- 当前话内的图片按页序从上到下排列，默认零间隙、占满阅读区域宽度。
- 保持图片比例，允许用户调整阅读宽度。
- 进度记录包含页码和该页内部的位置，适用于单张很长的条漫。
- 初始功能边界为当前话，章末展示下一话入口，不自动拼接整部漫画。

### 4.3 普通单页模式

- 一次显示一页，默认完整适配视口，不裁切图片。
- 支持轻触翻页和水平滑动翻页；放大后的图片拖动不翻页。
- 屏幕上、下、左、右区域独立配置为上一页、下一页或无操作。
- 中央区域固定呼出或收起菜单，不能因关闭其他点击区而丢失操作入口。
- 默认上方和左侧为上一页，下方和右侧为下一页；不随阅读方向静默更改用户映射。
- 区域不重叠：顶部和底部各占高度的 20%；中间区域左右各占宽度的 30%，剩余中央区域为菜单。四个角归顶部或底部区域。
- 设置中提供区域预览、立即试用和恢复默认。

## 5. 手机交互与性能

- 优先单手操作，菜单采用底部面板；主要按钮触控尺寸至少为 48 CSS 像素。
- 沿用原站的轻量视觉语言，阅读工具默认收起，不长期遮挡漫画内容。
- 适配横竖屏、安全区和浏览器地址栏展开/收起后的视口高度。
- 全屏 API 可用时提供全屏按钮；不可用时仍有隐藏工具栏的沉浸阅读，不把二者混为一谈。
- 区分轻触、连续滚动、翻页滑动、长按和多指操作；多指或放大拖动后不得误触翻页。
- 首版不加入双击缩放，避免和单击翻页产生等待及误触；保留双指缩放能力。
- 只为增强阅读器附近页面加载图片；远处保留尺寸占位，卸载其图片引用，避免返回时页面跳动。
- 必须检查隐藏原阅读区后的加载行为，不能再额外预加载一整套全章图片。不能宣称整个第三方页面有固定内存上限。
- 图片完成加载后释放不再使用的对象 URL，关闭阅读器后清理观察器和事件监听。
- 切换模式、方向或屏幕朝向时按逻辑页码和页内位置恢复锚点。
- 退出增强模式后恢复原阅读区、页面滚动和原站操作；脚本未启用时不接管页面手势。

## 6. 设置与阅读进度

- 通过 Tampermonkey 存储保存用户设置，使用带版本的独立键名。
- 漫画身份由来源标识和漫画标识共同决定，不使用漫画标题或临时签名 URL。
- 分别保存全局默认设置与单部漫画的模式、方向、宽度偏好。
- 阅读进度记录章节标识、逻辑页码和页内位置；在实际位置变化后节流保存。
- 不上传设置；首版不承诺跨设备同步。

## 7. 下载内容与命名

- 用户可以下载当前话、勾选多话或整部漫画。
- 默认固定当前漫画源，不自动把其他来源的同名章节混入任务。
- 任务确认页展示来源、所选章节、章节数量以及当前存储/保存能力。
- 章节编号采用完整目录中的正序位置，与当前界面的倒序显示或选中顺序无关。
- 若只选择第 10 话，文件夹仍保留对应的完整目录序号，不重编号为第 1 话。
- 章节和图片编号至少补齐四位；超过四位时自动扩展，不截断数字。
- 页序来自章节图片清单，不依赖图片请求完成顺序。
- 从文件内容和可信的 MIME 信息确定图片格式，保留 JPEG、PNG、WebP 等实际编码，不把任意图片改为 `.jpg`。
- 不缩放或重编码下载图片；默认采用 ZIP 的 STORE 方式打包已有压缩图片，减少手机 CPU 消耗。
- 文件名过滤路径分隔符、控制字符和非法名称；保留稳定数字前缀，避免重名覆盖及路径穿越。

输出结构：

```text
漫画名.zip
  漫画名/
    0001_第1话/
      0001.jpg
      0002.jpg
    0002_第2话/
      0001.webp
      0002.webp
    download-report.json
```

报告记录来源、目录及页数对照、结果和失败原因，不写入临时签名或完整敏感请求信息。目标始终是一个 ZIP，不自动改成每话一个 ZIP 或多个分卷。

## 8. 手机下载流水线

### 8.1 请求与恢复

- 目录解析、图片请求、缓存、打包和最终保存是独立阶段。
- 章节图片链接按需解析；恢复任务时重新解析尚未完成图片的链接，不长期复用已过期 URL。
- 手机默认同时最多请求两张图片，章节解析串行，避免请求突发。
- 每张图片总尝试次数最多为三次；网络错误和可重试服务错误采用退避。
- 遇到 429 时全局放慢请求，并遵守可读取的 `Retry-After`；等待期间可取消。
- 鉴权失败或过期链接只通过原有章节解析流程刷新；不绕过登录、付费或访问限制。
- 验证响应确为图片后再记录完成，不把 HTML 错误页、空响应或中断文件写成成功图片。
- 完成标记必须晚于缓存持久化，同时记录字节数和内容校验和；恢复时核对缓存存在、长度与校验和一致。
- 当目录或页数变化时提示重新核对，不静默把不同版本拼成一本。
- 提供暂停、继续、取消和失败重试；取消后的缓存由用户选择保留或清理。
- 同一任务只允许一个页面持有执行权；恢复前获取任务锁，检测到其他标签页正在处理时不重复下载或写入。
- 恢复的单位是已经完整缓存的图片，不承诺单张图片的 HTTP 字节断点续传。

### 8.2 存储与打包

- 优先检测并使用 OPFS 保存临时图片与输出 ZIP，ZIP 通过流式写入构建，避免把整包转换成内存中的 `ArrayBuffer`。
- OPFS 不可用时，使用 IndexedDB 保存图片缓存；无可用持久缓存时，只提供明确标识的有限容量、当前会话下载。
- 没有可写入磁盘的 ZIP 输出路径时，内存兼容模式的首版保守上限为 100 MiB；这是保护阈值，不是任意设备的安全保证。
- 在兼容模式开始前展示上限；长度未知时持续检查累计大小，达到阈值即暂停并说明原因，不等最终打包才发现超限。
- 使用浏览器存储估算做预检查，但把结果视为估算；捕获实际写入中的配额不足或存储失效。
- 保留图片缓存再生成 ZIP 会同时占用两份内容的存储，任务界面必须说明并为打包预留空间。
- 空间不足时暂停并保留可用的完成项，不转而尝试无限内存打包。
- 只操作脚本自己命名空间内的缓存；不得清空整个站点的 IndexedDB 或 OPFS。

### 8.3 保存与任务状态

- 打包完成后显示明确的“保存 ZIP”按钮，由用户点击触发系统下载，避免手机浏览器丢失用户激活状态。
- 保存适配层检测 Tampermonkey 的下载能力；支持时使用 `GM_download`，否则提供基于文件/对象 URL 的手动保存入口。
- 不要求 `showSaveFilePicker()` 或 `showDirectoryPicker()`，不使用第三方服务器中转或外部 StreamSaver 服务。
- 旧版 Tampermonkey 不能直接传入 `File`/`Blob` 时，不能因为函数存在就认为该参数受支持。
- 明确区分“图片已缓存”“ZIP 已生成”“已交给系统下载”和“收到下载成功回调”。无法验证系统落盘时不得显示为已保存成功。
- 保存失败保留已生成的 ZIP，允许重新保存；不为了重试导出而重新下载整部漫画。
- 有缺页时默认不作为完整任务成功结束。允许用户明确选择导出部分结果，文件名增加 `_partial`，报告保留原始编号及缺页清单。
- 安卓切后台、熄屏或系统清理可能暂停/终止页面；提示长任务保持页面前台，下次打开提供手动恢复入口。
- 清除站点数据、卸载浏览器或缓存被系统回收后不能保证恢复；不承诺后台常驻下载。

## 9. 代码结构与职责

实现采用 TypeScript，构建为一个 `.user.js` 文件，使用经过固定版本管理的 ZIP 库并保留依赖许可说明。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 站点适配 | 识别漫画、来源、章节和图片清单，处理站内路由变化 | 不决定阅读布局或下载命名 |
| 阅读核心 | 逻辑页码、三种模式、手势、位置恢复 | 不依赖具体站点 DOM 细节 |
| 手机界面 | 底部工具栏、目录、设置、点击区预览、任务面板 | 不直接实现网络重试或 ZIP 编码 |
| 设置存储 | 版本化设置和阅读位置 | 不保存大体积图片 |
| 下载调度 | 队列、限流、暂停、取消、失败与任务恢复 | 使用适配器和缓存接口，不直接操纵阅读 DOM |
| 图片缓存 | OPFS/IndexedDB 能力检测、写入、核验和清理 | 只清理脚本专属数据 |
| ZIP 与保存 | 命名、报告、流式或受限打包、最终导出 | 不重新决定漫画页序 |

入口、路由监听和原站恢复逻辑必须可幂等初始化，重复进入章节不会重复挂载界面或监听器。

跨域请求只用于漫画内容所需的站点和图片来源；列明所需权限，不增加 Cookie 管理、全网匹配、账号读取或遥测能力。不能把网页文本作为代码执行。

## 10. 验收标准

### 自动化与本地验证

- 三种模式在手机竖屏和横屏尺寸下可用，无工具栏溢出，主要操作可触达。
- 左右阅读方向切换不反转逻辑页码或下载顺序。
- 点击区域边界、四角归属、无操作配置、中央菜单和缩放防误触均有测试。
- 模式/方向/视口变化后恢复同一阅读位置，长图不总是回到图片顶部。
- 路由切换、反复启用/退出和失败恢复后无重复界面或残留事件监听。
- 使用自制图片测试目录倒序、选章、番外/小数标题、重名、非法文件名、混合图片格式及编号扩展。
- 用故障样本测试超时、429、过期链接、HTML 错误响应、取消中的迟到回调及缓存配额不足。
- 恢复任务只跳过确实存在的完整缓存项；丢失/损坏缓存不会造成假成功。
- 生成 ZIP 后实际解包校验目录、页数、页序、图片字节和失败报告。
- 分别测试 OPFS 路径、无 OPFS 的受限路径和保存失败后重试。
- 示例站点检查与单元测试分开，不以某一漫画源成功代表全站所有来源成功。

### 安卓真机验证

- 在用户实际浏览器和 Tampermonkey 中安装产物，检查触控、双指缩放、横竖屏和系统返回行为。
- 下载一个小章节，再下载至少两个章节，确认系统保存的 ZIP 能解压且编号正确。
- 测试切后台后返回、主动刷新后恢复和最终保存权限失败的提示。
- 电脑上的移动视口测试不能冒充安卓真机结果；未完成的真机项目必须在交付说明中明确列出。

## 11. 参考与已知限制

- [云漫](https://mangayun.com)：本次真实页面观察；网站结构和各源可用性可能变化。
- [PixivBatchDownloader](https://github.com/xuejianxianzun/PixivBatchDownloader)：参考任务管理、命名、进度恢复和去重思路。该项目为 GPL-3.0 浏览器扩展，不直接复制其源码到本项目。
- [zip.js](https://github.com/gildas-lormeau/zip.js)：核实支持 Web Streams、增量写入和 Zip64，许可为 BSD-3-Clause；库能力不等于手机具备无限存储或导出能力。
- [MDN: OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)：站点私有存储不等于用户 Downloads 目录，受配额和站点数据清理影响。
- [Tampermonkey: GM_download](https://www.tampermonkey.net/documentation.php?q=GM_download)：下载可能未启用、没有权限或不受支持；直接传入 Blob/File 需要文档指定的新版本能力。

本规格不承诺任意大小整本下载、所有安卓 Chromium 变种行为一致、自动绕过源站限制或在系统终止浏览器后继续运行。

## 12. 下一阶段

用户审阅本规格后，制定实现计划，再按可测试的模块实现。实现阶段应先打通真实站点的单章读取和安卓保存最小闭环，再完成三种阅读模式、多章任务与故障恢复；最终交付安装文件、源码、测试结果和真机验证清单。
